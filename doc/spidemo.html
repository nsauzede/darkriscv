SPI on the DarkRISCV SoC

An SPI master in the I/O block, a bit-banged alternative driven from software, a 3-wire mode, a model of the sensor for simulation and a Verilator cosimulation. The target is the LIS3DH accelerometer soldered on the Trenz MAX1000 board. The same series of changes fixed the core, widened the GPIO, ported two FPGA boards and added the project's CI.

SPI · 1

Architecture

The core reaches the sensor through the bus bridge and the DarkIO block. Two masters can drive the same pins: darkspi in hardware, or software toggling the GPIO output port.

hardware master bit-banged master shared pins

With SPIBB defined, bit 3 of oport hands CSN and SCK to the bit-banged master. SDI/O is a tristate line: the idle master releases it, and in 3-wire mode it also carries the sensor's answer. In simulation, lis3dh_stub.v sits inside darksocv.v and returns, for OUT_X, the value software writes to oport[31:16].

SPI · 2

The register

One 32-bit word at 0x4000001C. Writing it starts a transfer; reading it returns the status and the received data. The layout was reworked during the review of PR #86: status and data share one 32-bit word, readable in a single access.

// 0xE8 = register 0x28 | read (0x80) | auto-increment (0x40)
*((volatile int *)SPI_MMADDR) = 0x00e80000;

// read WHO_AM_I (0x0F) in one 16-bit transfer
*((volatile short *)SPI_MMADDR) = 0x8f00;
char who_am_i = *((volatile char *)SPI_MMADDR) & 0xff;    // 0x33

From the comment block at the top of rtl/darkspi.v.

The spidemo firmware brings the sensor up with four transfers: 0x8F00 checks WHO_AM_I, 0x2077 sets CTRL_REG1 to 400 Hz with X, Y and Z on, 0x1FC0 enables the temperature ADC, and 0x2388 sets CTRL_REG4 to block data update and high resolution. In 3-wire mode, bit 0 of CTRL_REG4 (SIM) is set as well, so the sensor answers on SDI.

SPI · 3

One transaction

Reading WHO_AM_I takes 16 clock cycles: eight command bits out, eight data bits back. The LIS3DH uses SPI mode 3: the clock rests high, data changes on the falling edge and is sampled on the rising edge.

Read of register 0x0F, answer 0x33

Limits from the datasheet, noted in src/spidemo/SPIBB.md: clock period 100 ns minimum (10 MHz), chip-select setup 5 ns and hold 20 ns, SDI setup 5 ns and hold 15 ns, SDO valid within 50 ns.

SPI · 4

Two masters, one bus

The bit-banged master exists to check the hardware one independently, on the real sensor, and to try bus mechanics in software before writing RTL. 3-wire mode exercises the same idea I2C needs: one data line used in both directions.

In 3-wire mode the master drives the command bits on SDI, then puts the line in high impedance for the data phase and samples the sensor on the same pin. mosi_tri (oport bit 4) and rd (oport bit 5) give the bit-banged master the same control.

Bit-banging from a PC over the UART

The shell command bb writes oport once per hex digit. ser.py sends such commands over the serial port, so a whole SPI exchange can be typed from a PC.

./ser.py "set_bb 1" "bb 7 f b 9 b 8 a 8 a 8 a 9 b 9 b 9 b 9 b ..."
#  bit 3 enable · bit 2 CS · bit 1 clock · bit 0 data
#  7 = 0111  master disabled, pins released
#  f = 1111  idle: CS high, clock high
#  9 = 1001  CS low, clock low,  data 1
#  b = 1011  CS low, clock high, data 1   "9 b" sends a 1
#  8 = 1000  CS low, clock low,  data 0
#  a = 1010  CS low, clock high, data 0   "8 a" sends a 0

The sequence above sends 1, 0, 0, 0, 1, 1, 1, 1: the command 0x8F of the diagram.

SPI · 5

Simulation

The SPI path is tested without hardware, in two simulators.

Icarus Verilog and a sensor model

lis3dh_stub.v decodes the command byte like the real chip: it answers 0x33 to WHO_AM_I and, for OUT_X, returns the 16-bit value that software placed on oport[31:16]. In simulation the spidemo firmware runs itself as a test: it sets an expected value, reads it back through SPI, compares, and repeats for each master and for 4-wire and 3-wire. It prints Test OK. or Bad out_x, then a > that ends the simulation.

The firmware sets the divider to its minimum in simulation: at the default of 10000, a single transfer would take hundreds of thousands of clock cycles. rtl/lib/spi/darksocv.gtkw opens GTKWave on the SPI signals.

Verilator and ImGui

Verilator compiles the RTL into a C++ model. sim/Vdarksocv_gui.cpp drives it from an ImGui window with Run, Step, AutoStep and Reset, a clock checkbox and the LED register. Serial output through the model is slow, so NOBANNER=1 skips the boot banner.

// sim/Vdarksocv_gui.cpp
ImGui::Checkbox("Run", &run);
ImGui::SameLine(); if (ImGui::Button("Step")) { step = 2; }
ImGui::SliderInt("StepTime", &step_time, 1, 10);
ImGui::Checkbox("clk", &clk);
ImGui::SameLine(); if (ImGui::Button("Reset")) { reset = true; }
ImGui::Text("LED %08lX", (unsigned long)darksocv->LED);
SPI · 6

Run it

From the repository root. A rebuild needs a RISC-V cross compiler, named by CROSS and CCPATH in src/config.mk or on the command line.

# simulation, Icarus Verilog
make clean all APPLICATION=spidemo
gtkwave rtl/lib/spi/darksocv.gtkw &

# cosimulation, Verilator and ImGui
make clean all APPLICATION=spidemo NOBANNER=1 SPIBB=1 COSIM=1

# MAX1000 board, Quartus
make clean all BOARD=max1000_max10 APPLICATION=spidemo
make install BOARD=max1000_max10
screen /dev/ttyUSB0 115200

On the branch this page sits on, SPIBB is commented out in the three makefiles and the build is little-endian. The committed src/darksocv.mem is still the big-endian image, so use clean all to rebuild it.

On the board, the shell's sensor command reads OUT_X in a loop and lights one of the eight LEDs according to the tilt, rescaling as it sees new minimum and maximum values. whoami, spi16, iport, oport and bb give direct access to the bus.

Beyond SPI

Other changes

What each change did, why, and how.

Core · PR #76

A hold value in the decoder

What
The execute stage decodes the opcode into one-bit flags. While HLT stalls the pipeline, each flag must keep its value; XCUS (custom opcode) was loaded with XRCC (register operation) instead.
How
One character. Found by reading the line against its neighbours.
XRCC   <= HLT ? XRCC   : IDATAX[6:0]==`RCC;
- XCUS   <= HLT ? XRCC   : IDATAX[6:0]==`CUS;+ XCUS   <= HLT ? XCUS   : IDATAX[6:0]==`CUS;
I/O · PR #85

Byte lanes on the LED register

What
A one-byte store to the 16-bit LED register also overwrote the upper eight LEDs.
How
Honour the byte enables XBE: on 0001, write the low byte and keep the high one.
- 5'b01000: LEDFF <= XATAI[15:0];+ 5'b01000: LEDFF <= XBE == 4'b0001 ? {LEDFF[15:8], XATAI[7:0]}+                                    : XATAI[15:0];
I/O · PRs #82 and #88

Wider LEDs and GPIO

What
16 LEDs, then the LED and output port widened to 32 bits, and the GPIO input and output ports brought out of darkio to the top level.
Use
The bit-banged SPI master drives its pins from oport and reads SDO back on iport.
Core · PR #72 · Toolchain · PR #73

Two build fixes

What
The Harvard build declared four cache wires twice in darkbridge.v; an `ifndef __HARVARD__ guard removes the duplicates. Recent GCC moved CSR instructions into the Zicsr extension, so -march=rv32e became rv32e_zicsr.
Why
Neither build went through: the Harvard configuration on the duplicate declarations, the firmware on CSR instructions that RV32E without Zicsr no longer accepts.
Board · PR #80

Trenz MAX1000, Intel MAX10

What
A 10M08 FPGA with 8 LEDs, a 12 MHz oscillator, SDRAM and the LIS3DH. The SoC uses about 40% of the logic.
How
A board top.v, a vendor PLL from 12 to 32 MHz, and a RAM wrapper around altsyncram so Quartus infers block RAM. The generic darkram worked only with the __RMW_CYCLE__ workaround.
Board · PR #81

Terasic DE10-Nano under MiSTer

What
A Cyclone V 5CSEBA6 with 110K logic elements. The SoC and the MiSTer framework take about 10% of it.
How
The core runs inside the MiSTer framework; the bitstream is loaded from the MiSTer menu and the console reached over ssh with screen /dev/ttyS1 115200.
Build · PRs #74 and #75

Firmware build and CI

What
Standard CFLAGS, missing headers in CoreMark and a missing size_t. Then a GitHub Actions workflow, the project's only CI.
How
An Arch Linux container installs Icarus Verilog and a riscv32 toolchain, simulates the committed image, rebuilds everything and simulates again, on every push and pull request.

State

Open issues

What remains unfinished or known to be weak, with the next step for each.

Endianness

Upstream made big-endian the default on May 23, 2025, and returned to little-endian on July 2. The spidemo branch fell back to little-endian with the bit-banged master disabled, and its committed image was not rebuilt.

Nextrebase on upstream, rebuild the image, re-enable SPIBB and run the self-test in both byte orders.

The CI cannot fail on a fault

The simulation ends with $finish at the shell prompt and on an invalid instruction alike, and both exit with status 0. The job passes whenever the firmware builds and the RTL compiles.

Nextfail the job when the log lacks the prompt or holds invalid XIDATA, and add the spidemo self-test.

I2C

The bit-banged I2C, the I2C master and the sensor model stayed on branches. 3-wire SPI already provides the release-and-sample mechanism that SDA needs.

Nextan open-drain SDA through oport, checked against the model.

Cosimulation speed

Serial output through the Verilator model is slow enough that the boot banner had to become optional.

Nextmeasure where the time goes: the GUI refresh, tracing, or the clock stepping.

Board-specific RAM

The MAX10 and Cyclone V ports carry their own altsyncram wrapper and PLL instead of using darkram and darkpll.

Nextmove the Intel branch into rtl/darkram.v and rtl/darkpll.v.

Repeated switches

SPI, SPIBB and SPI3WIRE are set in sim/Makefile, src/Makefile and src/spidemo/Makefile each. Changing one alone builds RTL and firmware that disagree.

Nextdefine them once, in src/config.mk.
